🏔️ heapq — Fila de Prioridade

Um heap (monte) é uma estrutura em forma de árvore binária onde o menor elemento está sempre na raiz (topo). Isso é chamado de min-heap.

Min-Heap visual: 1 ← menor sempre no topo / \ 3 2 / \ 7 4 heapq em Python usa uma lista: [1, 3, 2, 7, 4] ↑ heap[0] é sempre o menor

Operações principais

import heapq

heap = []
heapq.heappush(heap, 5)    # insere 5
heapq.heappush(heap, 1)    # insere 1
heapq.heappush(heap, 3)    # insere 3

print(heap[0])              # 1 (menor, sem remover)

menor = heapq.heappop(heap) # remove e retorna o menor
print(menor)                # 1
🔶 Conexão com Java heapq em Python ≈ PriorityQueue em Java.
heappush() → pq.add()
heappop() → pq.poll()
Ambos são min-heap por padrão (menor sai primeiro).

Simulando Max-Heap: negar os valores

heapq é sempre min-heap. Para fazer um max-heap (maior sai primeiro), você nega os pesos ao inserir:

import heapq

heap = []
heapq.heappush(heap, -5)   # insere -5 (representa 5)
heapq.heappush(heap, -1)   # insere -1 (representa 1)
heapq.heappush(heap, -3)   # insere -3 (representa 3)

maior = -heapq.heappop(heap) # pop dá -5, negando: 5
print(maior)                  # 5 (o maior!)

🔪 bisect — Busca Binária Pronta

O módulo bisect faz busca binária automaticamente em uma lista já ordenada. Ele diz onde inserir um elemento para manter a lista ordenada.

import bisect

v = [10, 20, 30, 40, 50]

pos = bisect.bisect_left(v, 30)   # 2 (insere ANTES do 30)
pos = bisect.bisect_right(v, 30)  # 3 (insere DEPOIS do 30)

bisect_left vs bisect_right

Lista: [10, 20, 30, 30, 40] ↑ ↑ bisect_left(30): posição 2 (borda ESQUERDA das duplicatas) bisect_right(30): posição 4 (borda DIREITA das duplicatas) left → insere ANTES dos iguais right → insere DEPOIS dos iguais
Do Kahoot "Qual diferença entre bisect_left e bisect_right ao inserir duplicatas?" → Posição em borda
bisect_left = borda esquerda; bisect_right = borda direita.

📝 Strings: join vs +

Concatenar strings com + em um loop é ineficiente porque strings em Python são imutáveis — cada + cria uma cópia nova na memória.

Concatenando com "+": resultado = "" resultado = resultado + "A" → cria nova string "A" resultado = resultado + "B" → cria nova string "AB" resultado = resultado + "C" → cria nova string "ABC" 3 strings criadas = 3 cópias! Em 10.000 iterações = 10.000 cópias! ──────────────────────────────────────── Concatenando com join: lista = ["A", "B", "C"] resultado = "".join(lista) → UMA cópia final: "ABC" 1 string criada! Sempre 1, independente do tamanho. 
# ❌ Lento: cópias repetidas a cada iteração
resultado = ""
for letra in lista:
    resultado += letra     # cria nova string toda vez

# ✅ Rápido: uma cópia final
resultado = "".join(lista) # junta tudo de uma vez
🔶 Conexão com Java É o mesmo problema de String += vs StringBuilder.
"".join(lista) em Python ≈ sb.toString() em Java.
⚠️ Do Kahoot "Por que concatenar com '+' em loop é trabalhoso?" → Cópias repetidas
"Como concatenar muitas strings de forma linear?" → "".join(lista)
"Como join reduz o custo?" → Uma cópia final

🎯 Critério de Escolha: list vs deque vs heapq

Cada estrutura resolve um problema diferente. O critério de escolha é: quais operações você precisa fazer com mais frequência?

FIFO (fila)dequeappend+popleft são O(1)
